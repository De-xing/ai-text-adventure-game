软件非功能规格说明书 (Non-Functional Specification)
项目名称：AI Text Adventure C++
文档版本：v1.0
编写日期：[2026.10.17]

1. 可用性 (Usability)
定义：系统的易学性、操作效率、用户满意度。

需求ID：NFR-U-01

描述：控制台交互界面应具备良好的可读性和视觉分层，便于玩家快速获取信息。

验收标准：

剧情文本、状态面板（血量/背包）、选项列表必须使用 ANSI 转义字符进行颜色或样式区分（如：血量为红色，选项为绿色）。

新玩家在无需阅读外部说明书的情况下，能在首次进入游戏后 1 分钟内完成“生成场景 -> 做出选择”的完整交互。

玩家输入无效指令时，系统应给出明确提示（如“请输入有效选项编号”），且不中断游戏。

需求ID：NFR-U-02

描述：支持快捷输入以提高游戏沉浸感和操作效率。

验收标准：

玩家可直接输入数字（1, 2, 3...）选择行动选项，无需输入完整文本。

支持常用系统快捷指令（如输入 save 存档、load 读档、quit 退出）。

2. 可靠性 (Reliability)
定义：系统的故障频率、可恢复性、数据安全性、输出的准确性。

需求ID：NFR-R-01 (防篡改与数据安全)

描述：存档系统必须具备数据完整性校验，防止玩家通过修改本地文件作弊。

验收标准：

存档文件必须经过加密（如 AES 或基于哈希的签名校验）。

若玩家使用文本编辑器强行修改存档中的生命值或物品数量，系统在读取该存档时必须在 1 秒内识别出“存档损坏/非法”，并拒绝加载，提示玩家重新开始。

需求ID：NFR-R-02 (大模型输出容错)

描述：系统必须对 LLM 返回的内容进行鲁棒性解析，防止因大模型幻觉或格式错误导致 C++ 程序崩溃。

验收标准：

当 LLM 未按要求的 JSON 格式返回，或缺失关键字段（如 scene_description）时，nlohmann/json 解析器不崩溃。

具备自动重试机制（重试次数 ≤ 2 次），若重试仍失败，降级为预设的兜底文本，并提示“AI 陷入混乱，请重新输入”。

需求ID：NFR-R-03 (网络与外部依赖异常处理)

描述：在网络波动或云端 API 服务中断时，系统能优雅降级，不丢失用户当前进度。

验收标准：

云端模式下，HTTP 请求超时时间设置为 15 秒。

当网络断开或 API Key 失效时，系统捕获 libcurl 异常，提示“网络连接失败”，保留当前的血量和背包状态，允许玩家稍后重试。

3. 性能 (Performance)
定义：系统的响应时间、吞吐量、资源占用。

需求ID：NFR-P-01 (本地核心逻辑执行效率)

描述：C++ 本地业务逻辑（如状态计算、背包遍历、加解密）必须极速响应，不能成为瓶颈。

验收标准：

单次本地状态更新（包含扣血、物品变更）的执行时间 ≤ 10 毫秒。

存档加密与写入磁盘的时间 ≤ 100 毫秒。

游戏主循环空闲时，CPU 占用率 ≤ 5%。

需求ID：NFR-P-02 (LLM 生成延迟)

描述：大模型生成剧情的速度需满足玩家的阅读耐心。

验收标准：

云端模式：从发出 API 请求到首字符（TTFT）返回的延迟 ≤ 2 秒；端到端完整场景生成 ≤ 5 秒。

本地 Ollama 模式（在推荐配置 16G RAM / 6G VRAM 下）：生成包含 100-150 字的场景描述与 3 个选项，耗时应 ≤ 10 秒。

4. 支持性 (Supportability)
定义：可维护性、可配置性、可测试性、可扩展性。

需求ID：NFR-S-01 (配置与可扩展性)

描述：软件需支持双模式（云端/本地）的无缝切换，且相关配置不得硬编码。

验收标准：

API Key、Ollama 地址、模型名称等配置信息，必须通过读取本地的 .env 或 config.json 文件加载。

玩家只需修改配置文件并重启程序，即可在“云端模式”和“本地离线模式”之间切换，无需重新编译源码（符合 OCP 开闭原则）。

需求ID：NFR-S-02 (跨平台可测试性)

描述：代码应具备良好的可移植性和可测试性。

验收标准：

使用 CMake 作为构建工具，源代码可在 Windows (MSVC)、macOS (Clang)、Ubuntu (GCC) 下成功编译通过。

核心业务逻辑（如 Player::modifyHp 和 SaveManager::encryptData）的单元测试覆盖率 ≥ 60%。

需求ID：NFR-S-03 (日志与可观测性)

描述：系统必须具备完善的日志记录功能，便于开发人员排查 Bug。

验收标准：

日志需分级输出（INFO, WARNING, ERROR）。

日志需记录每次 LLM 请求的 Prompt 长度、响应耗时。

安全约束：日志中严禁输出完整的 API Key 和明文密码，敏感信息必须脱敏（如 sk-****abcd）。
