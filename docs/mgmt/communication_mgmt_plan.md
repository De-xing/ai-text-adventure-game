# 产品团队沟通管理计划

## 1. 沟通管理矩阵

| 沟通内容 | 沟通频度 | 沟通方式 | 产出物 |
| :--- | :--- | :--- | :--- |
| **分析阶段**：确认游戏核心机制、5W1H工程问题定义、目标用户画像 | 每周1次 | 面对面 | 《问题定义文档 (problem_definition.md)》、需求确认记录 |
| **分析阶段**：分配各成员任务，建立GitHub仓库与看板 | 即时 | 面对面 | 初始化的Kanban看板、Issue任务分配清单 |
| **设计阶段**：讨论C++类图设计（特别是LLMClient接口隔离）、云端/本地双模式架构 | 即时/按需 | 面对面交流 + 白板绘图 / draw.io | 《系统架构图 (UML)》、《技术选型调研报告》 |
| **设计阶段**：确定LLM Prompt设计（如何让模型返回结构化JSON数据） | 每天 | 即时通信工具 (微信/QQ) | Prompt模板草案、接口测试脚本 |
| **开发阶段**：每日代码进度同步、今日计划及阻塞问题（每日开会） | 每天 | 微信群文字同步 | 站会记录、更新后的看板进度 |
| **开发阶段**：核心代码合并与代码审查 (Code Review) | 即时 | 面对面 | 经过评审的C++代码 (合并至develop分支)、评审意见 |
| **测试阶段**：交叉测试（C++逻辑、存档加密、LLM响应速度）与Bug提交 | 每天 | 项目协作平台 (GitHub Issues - Bug Tracker) | 测试用例文档、Bug修复记录 |
| **测试阶段**：云端API断网模拟、Ollama内存溢出测试反馈 | 即时 | 即时通信工具 + 面对面 | 异常处理代码更新、边界条件测试报告 |
| **发布阶段**：依赖库版本确认（libcurl/json）、CMake编译指令核对 | 每周1次 | 面对面 + 项目仓库 | 《用户手册》、《构建与部署说明 (README.md)》 |
| **答辩阶段**：整合答辩材料、Demo演示流程彩排与分工 | 每天 | 面对面交流 / 视频会议 | 答辩PPT（或Slidev链接）、演示视频、演练记录 |
| **复盘阶段**：总结项目开发过程中的经验教训，确认遗留技术债 | 每周1次 | 视频会议 + 协作平台 (Discussions) | 《项目总结与复盘报告》 |

## 2. 说明与注意事项
- 条目的顺序按照生命周期排列：分析、设计、开发、测试、发布、运行维护。
- 沟通频度定义了各项活动的周期（即时、每天、每周等）。
- 沟通方式涵盖了团队常用的正式与非正式渠道。
- 产出物作为沟通闭环的凭证，需统一归档至项目的 `docs` 目录中。
