# 产品团队风险管理计划

## 1. 风险管理矩阵

*说明：风险是指存在不确定的问题。制定风险管理计划的目标是提高正面风险的概率和/或影响，降低负面风险的概率和/或影响，提高项目成功的可能性。*

| 风险名称 | 所属维度 | 风险说明 | 影响程度 | 对工作量的影响 | 对进度和成本的影响 | 优先权 | 跟踪频率 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **LLM返回格式解析失败** | 技术 | 大模型生成的剧情没有严格遵循JSON格式，导致C++的 `nlohmann/json` 解析崩溃或玩家无法选择选项。 | 高 | 高 | 高 | 高 | 每天 |
| **本地Ollama性能瓶颈** | 资源 | 测试机显存/内存不足（低于16G/6G），导致 `qwen2.5:7b` 运行卡顿或OOM崩溃，影响演示。 | 高 | 低 | 中 | 高 | 即时 |
| **外部API服务不稳定/限流** | 外部因素 | 调用云端API时遇到网络断连、API Key欠费或并发限制，导致游戏无法继续。 | 中 | 中 | 中 | 中 | 每周 |
| **C++内存泄漏与崩溃** | 技术 | 游戏运行中，指针或资源（如libcurl句柄）未释放，导致长时间运行后内存溢出。 | 高 | 高 | 中 | 高 | 每周 |
| **Git合并冲突 (C++特性)** | 项目管理 | 多人同时修改C++头文件（`.h`）或CMake配置，导致复杂的合并冲突。 | 中 | 中 | 中 | 中 | 每天 |
| **依赖库环境配置差异** | 项目管理 | 团队成员的OS环境不同（如Mac/Windows），导致 `libcurl` 或 `nlohmann/json` 编译失败。 | 中 | 中 | 低 | 低 | 每周 |
| **存档加密机制被绕过** | 技术 | 加密算法过于简单（如简单异或），玩家轻易篡改血量/物品，破坏游戏规则。 | 低 | 低 | 低 | 低 | 每月 |
| **人员因病/事假缺席** | 资源 | 核心开发人员（如负责C++主逻辑或LLM对接的成员）无法参与，导致进度停滞。 | 高 | 高 | 高 | 中 | 即时 |

## 2. 重点风险应对预案
- **应对 LLM 格式解析失败**：在 Prompt 中明确要求“仅返回JSON”，并在 C++ 端编写兜底重试逻辑；或使用大模型的结构化输出功能（如 JSON Mode / 约束解码）。
- **应对 Git 冲突**：规定所有 `.h` 头文件的修改必须在群内提前通知；开发人员每天开工前必须先 `git pull` 拉取最新的 `develop` 分支。
- **应对 Ollama 性能瓶颈**：在代码中设置请求超时机制，并提供便捷的命令行参数，允许在演示时快速切换到云端 API 模式。
