# EchoQuest 答辩补丁包：时间控制、演示故障与表达技巧

> 这是 `speech-script.md` 和 `qa-prep.md` 之外的“现场执行层”。
> 作用：时间不够时怎么砍、设备出问题怎么救、被追问时怎么接、哪些话绝对不能说。

---

## 一、三个版本的开场（按剩余时间选）

### 30 秒版（电梯陈述）

> EchoQuest 是一条把自然语言故事设定编译成可玩互动叙事的流水线。用户写一段背景，系统生成 6–16 个节点、2–4 个选项、1 或 3 个结局，程序负责校验连通性和结局可达，模型只负责写内容。我们的差异不是“会生成”，而是“生成之后一定玩得下去”。

### 1 分钟版

> 通用模型给的是一段文本，读完就结束；传统创作工具要求你会搭树、写脚本。EchoQuest 把中间的结构工作接过来：先让模型产出故事图，程序校验，再按图写正文，最后编译成可编辑、可存档、可游玩的故事。
>
> 当前是原生前端 + Python 标准库服务 + Nginx 的原型，API Key 只在服务端，模型失败会自动降级到本地引擎。
>
> 我们最大的缺口也说清楚：作品只在浏览器，没有账号和跨设备分享；这是下一步第一优先级。

### 3 分钟版

> 按“问题 → 方案 → 证据 → 边界”四段讲：
>
> 1. 问题：模型边写边迷路，断链、结局不可达、成本不可控。
> 2. 方案：结构先于文本，两段式生成 + 程序校验 + 条件修复 + 编译。
> 3. 证据：22 个测试、Pylint 10.00、最大圈复杂度 62→17、7 条用户路径通过。
> 4. 边界：没有数据库/RAG/账号/审核中台，作品在 localStorage；下一步先做持久化。
>
> 最后一句：我们不是把模型做得更自由，而是把模型放进一个有断言的编译器里。

## 二、时间不够时，按这个顺序砍

| 剩余时间 | 保留 | 砍掉 |
|---|---|---|
| 8 分钟 | 全稿 | 原则页的展开、部分技术选型 |
| 6 分钟 | 一句话价值 → 产品问题 → 结构先于文本 → Agent 四件事 → 边界 → 总结 | 用户画像细节、差异化大表、代码统计 |
| 4 分钟 | 一句话价值 → 两段式 → 校验/降级 → 边界 | 原则、架构细节、质量数字 |
| 2 分钟 | 30 秒版 + 演示 | 全部支撑页 |

**永远不要砍掉“边界页”**。主动说没做什么，比被问出来更加分。

## 三、演示故障分支

| 故障 | 现场动作 | 话术 |
|---|---|---|
| 模型超时/额度不足 | 等 2 秒，刷新；仍失败就继续，页面会降级 | “真实模型不可用，系统自动切本地引擎；这就是失败不白屏的设计。” |
| 生成很慢 | 不反复点，指阶段条 | “现在卡在撰写阶段，架构和校验已经完成；我们看阶段和 token。” |
| 页面 502 | 不要切 PPT 遮掩，直接说 | “后端服务掉了，我先用本地静态副本演示前端；服务端问题我答辩后查日志。” |
| 网络断开 | 打开提前准备的本地副本/截图 | “现场网络不稳，我用本地缓存走同一套流程。” |
| 工坊改坏了 | 刷新，或点整局重生成 | “节点编辑是可逆的，最坏情况重生成整局。” |
| 存档读不出来 | 不反复点，换预览 | “存档是 localStorage，换浏览器会丢；这正是我们说的持久化缺口。” |
| 现场没有 API Key | 直接用本地引擎 | “当前演示机没配 Key，走本地降级；在线版会调用真实 Agent。” |

**演示前必须准备：**

- 一个已经生成好的作品，避免现场等待。
- 一张工坊截图、一张质量对比图，断网时用。
- 本地 `server.py` 已启动；在线地址和 IP 都试过。
- 浏览器只留一个标签页，关闭无关插件。

## 四、被问住时的 4 个转场句

1. **承认边界：**
   > “这个点目前没有做，我不把它说成已完成。当前阶段的取舍是先把生成链路跑通。”

2. **从设计转现状：**
   > “这是设计稿，不是线上实现。当前实际落地的是……”

3. **从单点转全局：**
   > “这个问题落在我们的‘边界页’，我先说结论，再补原因。”

4. **不会答：**
   > “这个我没有足够数据，不能现场编。我的判断是……，回去会用……验证。”

不要用：

- “这个不重要。”
- “用户不会这么用。”
- “模型自己会处理。”
- “我们全部做完了。”

## 五、评委类型与应对

| 评委类型 | 关心什么 | 应对 |
|---|---|---|
| 技术评委 | 真做了吗、边界、数据 | 主动区分“现状/设计”，给代码路径和测试命令 |
| 产品评委 | 用户是谁、凭什么用、怎么传播 | 讲 11 人访谈、社团场景、分享缺口 |
| 管理/评审 | 成本、风险、合规、计划 | 讲限流、降级、下一步优先级，不空谈愿景 |
| 刁钻评委 | 找矛盾 | 不硬撑；承认口径问题，给修正动作 |

## 六、答辩前 7 个“必须改或必须承认”的点

1. **31 张表 / SQLite**：当前没有数据库。改成“目标数据模型”，或现场承认。
2. **ReAct**：当前游玩期是本地关键词，不是 ReAct。
3. **7 个 Function Calling 工具**：当前是三个固定阶段接口，工具 Schema 是设计。
4. **MIT License**：仓库没有 LICENSE；补上或删掉。
5. **85% 通过率 / 45s P95**：目标值，不是当前实测。
6. **鉴权**：没有账号鉴权，只有同源校验和限流。
7. **157 条测试**：0/157 按原工程执行，当前 22 个 Python 测试通过。
