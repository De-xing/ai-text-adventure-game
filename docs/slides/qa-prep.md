## 二、8 个核心问题（必须背熟）

### Q1. 这算 Agent 吗？还是只是工作流？

**短答：**

> 生成期是确定性 Agent 流水线，游玩期目前是规则驱动的交互；我们没有把“自主决策”当成卖点，而是把“可控地完成叙事任务”当成 Agent 的工程形态。

**展开：**

- Agent 不等于“模型自由乱跑”。我们把它拆成五个问题：编排、工具、记忆、护栏、知识。
- 当前落地最深的是编排、结构校验、工具边界和失败降级；记忆/知识是下一阶段。
- 这样做的原因是：生成任务需要可复现、可测试、可回滚，不能让模型每一步自由发挥。

**不要说：**

- “我们是一个完全自主的多 Agent 系统。”——不是。
- “游玩期已经用 ReAct。”——当前自由行动是本地关键词，不是 ReAct。

---

### Q2. 为什么不用 LangGraph / LangChain？

**短答：**

> 当前只有 2–3 次模型调用、单机 3 并发，引入框架带来的是调试面和依赖，不是能力提升；我们复用了它的思想，没有复用它本身。

**展开：**

- 我们用的是固定阶段状态机：架构 → 校验 → 撰写 → 校验 → 条件修复 → 编译。
- 工具 Schema、状态机、checkpoint 的思想都借鉴了，只是用原生代码实现。
- 触发迁移的条件：需要多轮状态持久化、断点恢复、人工审核节点、多 Agent 协作，或者并发上到 50+。那时先换 FastAPI，再评估 LangGraph。

**不要说：**

- “LangGraph 太重，我们永远不用。”——是有触发条件的。

---

### Q3. 你的“记忆”是不是就是上下文窗口？

**短答：**

> 不是。上下文是装配结果，记忆是存储层。当前演示版是 localStorage + 故事圣经；三层记忆和向量检索是设计，不是已上线。

**展开：**

- 当前：作品、存档、结局在 localStorage；每次生成带故事圣经；没有 Redis。
- 设计：会话记忆（Redis TTL）、单局工作记忆（run steps）、长时记忆（摘要/向量）。
- 上下文按预算装配：系统指令、硬约束、当前节点、最近交互、摘要、检索结果，各有上限。
- 超长时按固定优先级裁剪，不让模型决定删什么。

**不要说：**

- “已经做了 Redis / pgvector。”——没有。

---

### Q4. RAG、知识图谱、31 张表，真的做了吗？

**短答：**

> 没有。当前仓库没有数据库，也没有向量检索和图查询。31 张表是目标数据模型，不是已上线实现；这正是我们能力边界里明确写的“还没做”。

**展开：**

- 当前作品在浏览器 localStorage；服务端只保存 API Key。
- RAG、pgvector、GraphRAG 是架构文档里的阶段 2/3。
- 我们已经把数据模型、硬约束、上下文预算设计清楚，但没有把它们伪装成已完成。
- 下一步第一优先级不是 RAG，而是作品服务端持久化，因为分享是最大的产品缺口。

**不要说：**

- “表已经建好了，只是没启用。”——仓库没有 schema，现场查不到。
- “知识图谱已经在跑。”——没有图查询引擎。

---

### Q5. 为什么不用 Function Calling？7 个工具在哪？

**短答：**

> 当前是固定阶段 HTTP 接口，不是模型自主选择工具。7 个工具和 JSON Schema 是目标设计；当前模型没有工具选择权，这反而让边界更可控。

**展开：**

- 当前真正存在的是 `/api/agent/architect`、`/write`、`/repair` 三个模型接口，加上前端本地校验/编译。
- 模型不能访问数据库、文件系统、网络，也不能直接改状态。
- 如果以后接 Function Calling，只读/纯生成工具可以放开；改结构、改状态、放行内容的工具仍然由程序固定调用。

**不要说：**

- “我们已经实现了 7 个 Function Calling 工具。”——没有。
- “模型可以自己选工具。”——当前不是。

---

### Q6. 157 条测试通过了吗？为什么只有 22 个？

**短答：**

> 没有。原始 157 条用例依赖 Vitest/Playwright/SQLite 的测试工程，而仓库里没有那套资产，执行报告里标的是 `0/157 BLOCKED`，不是通过。当前可执行的是 22 个 Python unittest + 7 条用户路径。

**展开：**

- 22 个测试覆盖：JSON 容错、拓扑排序、蓝图校验、正文校验、HTTP 路由、同源拒绝、错误脱敏。
- 7 条用户路径覆盖：发现页、生成、短背景拦截、XSS、移动端、预览模式、file://。
- 157 条测试文档的路径是 `code/frontend/js/*`、`tests/`、`schema.sql`，当前仓库实际是 `assets/*`，没有 SQLite。不能把“用例写了”当成“用例通过”。

**不要说：**

- “157 条全部通过。”——这是最容易被现场拆穿的。
- “22 个就是全部测试。”——还有 157 条待适配。

---

### Q7. 成本怎么控？一次生成多少钱？

**短答：**

> 单篇 2–3 次短调用，不做长上下文；失败只重跑失败阶段；限流 8 次/小时/IP、300 次/天、并发 3；成本是设计出来的，不是省出来的。

**展开：**

- 架构一次、撰写一次，结构不合格才触发第三次修复。
- 中间结果在前端保留，编译失败不需要重新调模型。
- 失败优先降级本地引擎，不无限重试。
- 单篇 token 和耗时在 Agent Trace 里可见；目前没有成本看板，只有明细。

**不要说：**

- “成本很低，几乎不花钱。”——按额度说话，别拍脑袋。
- “我们做了精确的 P95 成本统计。”——没有看板。

---

### Q8. 内容安全怎么办，尤其未成年人？

**短答：**

> 当前只有提示词约束、同源/限流、请求体限制和 HTML 转义，没有完整审核中台。公网运营前必须补输入/输出审核、未成年人分级、举报下架和 PII 脱敏。

**展开：**

- 已做：API Key 服务端、Nginx 拒 `.secrets`、同源校验、请求体 48KB、IP 限流、前端转义、模型输出不执行。
- 未做：审核服务、敏感词归一化、PII 自动脱敏、人工审核后台、投诉流程。
- 这是“公开上线”的前置条件，不是可选项。

**不要说：**

- “我们已经做了完整内容审核。”——没有。
- “模型自己会拒绝。”——不能作为合规方案。

## 三、高频追问（按可能性排序）

### Q9. 你的创新点是什么？不就是调了个大模型吗？

**短答：**

> 创新不在“用了模型”，而在“把模型放进一个有断言的编译器”：先图后文、结构校验、条件修复、失败降级。

**证据：**

- 单次长提示词的问题：断链、结局不可达、选项数量漂移、成本不可控。
- 两段式后：结构在写正文前被验证；校验器是纯函数；修复只重跑局部。
- 这是工程抽象层的创新，不是模型能力创新。

---

### Q10. 为什么不用 React / Vue？前端是不是太原始？

**短答：**

> 当前只有 4 个视图、状态集中、没有多人协作，引入框架和构建链的收益小于成本。触发条件是页面数翻倍或需要协同编辑。

**补充：**

- 原生 SPA + Hash 路由，部署就是静态文件，老师/评委本地 `python server.py` 就能跑。
- 代价是 `app.js` 较大、缺少组件化；这是明确的债，不是“永远正确”。

---

### Q11. 为什么作品只存在浏览器？分享怎么做？

**短答：**

> 这是当前最大的产品缺口。下一步第一优先级是作品服务端持久化，`games`/`share_links` 只是设计，没上线。原型期用 Markdown 导出过渡。

**不要辩解：**

- 不要说“本地存储更安全”。对用户来说，跨设备打不开就是缺陷。
- 承认：A 用户的作品 B 用户看不到，复制链接也无效。

---

### Q12. 为什么选 DeepSeek？被供应商绑定了吗？

**短答：**

> 选型第一指标是 JSON 结构稳定性，第二是中文叙事和成本。接口是 OpenAI-compatible，换模型只改 `baseUrl / model / apiKey` 三项。

**补充：**

- 没有做完整横向评测；评估集已建，实测数据还在补。
- 不把“最强模型”当目标，创作质量边际收益递减，成本和稳定性更重要。

---

### Q13. API Key 泄露了怎么办？有人刷你的额度怎么办？

**短答：**

> Key 只在服务端 `.secrets`，600 权限，Nginx 拒绝隐藏路径，Git 忽略；限流 8 次/小时/IP、300 次/天、并发 3。若泄露立即轮换，不依赖删除文件。

**补充：**

- 当前没有账号和用户级配额，公网恶意刷量仍可能；生产要加 WAF、登录或网关配额。
- 限流是单机内存，重启清零，不能跨实例。

---

### Q14. 并发上来怎么办？为什么只用一个进程？

**短答：**

> 当前单进程 + 3 并发，适合演示。限流和信号量在进程内，多 worker 不共享，所以不建议直接加 worker。并发上 50 先换 FastAPI + 队列 + Redis，再考虑多实例。

**补充：**

- 无状态部分可以横向扩，但限流、并发和任务状态要先外置。
- 当前没有任务队列，请求是同步等待模型。

---

### Q15. 你的 85% JSON 通过率、45 秒 P95 是怎么测的？

**短答：**

> 这些是目标值，不是当前实测结论。当前能展示的是 Agent Trace 里的阶段耗时、token 和校验 issues；完整评估集回归还没形成看板。

**如果追问：**

- 不能说“已经达到 85%”。
- 可以说“指标定义在架构文档 §1.4，当前有校验器可以统计，下一步补离线评估集和报表”。

---

### Q16. 为什么不做小程序 / App？

**短答：**

> 不是没想到，是内容审核资质和未成年人保护这关，在有内容链路验证之前不该碰。先用 Web 把生成、校验、游玩跑通。

---

### Q17. 这个项目你个人做了什么？

**准备方式：**

- 用“我负责的模块 + 可验证产物”回答，不要只说“我写了全部”。
- 示例：我负责 Agent 流水线、结构校验器、服务端密钥与限流、测试与部署；具体可以打开 `server.py` 的 `do_POST`、`agent.js` 的 `generate`、`tests/`。
- 如果团队分工不同，按真实情况替换，别背错。

---

### Q18. 如果给你一个月，你先做什么？

**短答：**

> 第一，作品服务端持久化，让分享成立；第二，内容审核和 PII 脱敏，让公网运营有底线；第三，评估集和可观测性，让“更好”可证明。RAG 和多 Agent 排在后面。

## 五、不会答时怎么说

不要编。用这个四步：

1. **承认**：“这个点我们目前没有做/没有测。”
2. **解释**：“当前阶段的取舍是……”
3. **给计划**：“下一步会先做……”
4. **给验证**：“验收标准是……”

示例：

> “这个我们目前没有做。当前阶段优先保证生成链路可玩，所以没有接账号和作品库。下一步先做服务端持久化，验收标准是同一链接在另一台设备能打开同一作品。”
